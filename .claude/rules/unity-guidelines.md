# Unity 프로젝트 개발 지침

> Unity 버전, 대상 플랫폼, 콘텐츠 루트 폴더, 작업자 매핑 등 프로젝트 고유값은 프로젝트 `CLAUDE.md`에 정의한다.

## 1. 개발 환경
- 프로젝트에 지정된 Unity 버전을 기준으로 한다. 승인 없이 Editor나 패키지를 업그레이드하지 않는다.
- 대상 플랫폼(모바일, WebGL 등)의 성능, 화면 방향, 화면 비율 차이를 고려한다.
- Scene이나 에셋을 수정하기 전에 공식 Unity 연동 기능에서 확인할 수 있는 실제 프로젝트 상태를 조사한다.

## 2. 프로젝트 폴더
새 콘텐츠는 프로젝트 콘텐츠 루트(`Assets/<Project>/`) 아래에 배치한다. 권장 구조:

```text
Assets/<Project>/
├── Art/
├── VFX/
├── Audio/{BGM,SFX}
├── Animations/
├── Prefabs/
├── Scenes/{Main,<작업자>...}   # 6장 참고
├── Scripts/
└── Settings/
```

- 기존 Editor 빌드 스크립트는 `Assets/Editor/`에 있을 수 있다.
- 기존 폴더 구조를 따르며 중복 폴더를 만들지 않는다.

## 3. Scene 및 에셋 보호
- `.meta` 파일과 GUID 참조를 보존한다. 에셋을 임의로 재생성하지 않는다.
- Scene/Prefab 전체를 불필요하게 재작성하지 않는다. Component 또는 필드 변경 전에 직렬화 참조를 확인한다.
- 명시적 승인 없이 Assembly Definition 파일이나 신규 패키지를 추가하지 않는다.
- Input System 및 렌더 파이프라인은 프로젝트의 현재 설정을 확인하고 따른다.

## 4. 스프라이트 및 성능
- 팀이 합의한 에셋 임포트 규격과 실제 사용 중인 스프라이트 크기를 따른다. 제안만으로 기존 에셋을 일괄 변경하지 않는다.
- Pivot, Sorting Layer, 애니메이션 연속성, 플랫폼 텍스처 압축을 유지한다.
- 이슈 범위나 승인 없이 Addressables, 신규 빌드 자동화, 렌더 파이프라인 변경을 도입하지 않는다.

## 5. 검증
- 가능한 경우 Unity Console 및 컴파일 상태, 관련 Scene/Prefab, Play Mode 동작, 대상 플랫폼 영향을 확인한다.
- 공식 플러그인이 특정 Editor 작업을 지원하지 않으면 존재하지 않는 명령어를 만들어 내지 말고 한계를 보고한다.
