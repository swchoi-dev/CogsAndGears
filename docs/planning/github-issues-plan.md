# GitHub Issues 최종 등록안 — 생성 승인 대기

- 기준일: 2026-11-10. 실제 GitHub 쓰기 없음. 상위 **11개**, 하위 **45개**(T01~T39 필수·고유 MVP·제출 준비, T40~T45 후순위), 최대 **56개** 생성 후보다.
- E/T ID는 이 문서 내부 식별자이며 GitHub Issue 번호가 아니다. 등록 시 실제 번호를 받아 치환한다. 완료된 기반 작업은 신규 구현 Issue로 만들지 않는다. 등록 직전 이미 완료된 작업은 재분류하고 생성 수를 다시 확인한다.
- 근거: [조사 기록](implementation-audit.md), [요구사항 추적표](mission-requirements.md), [일정·위험](../roadmap.md). PDF 페이지는 제공된 실제 9페이지 파일 기준이다.
- 사용자는 Unity 구현과 Git 브랜치·Commit·Push·PR·Merge를 직접 수행한다. Codex는 분석·문서·Issue 초안과 Git 제안만 담당한다. 이 작업별 지시가 기존 일반 Harness의 승인 후 Git 수행 가능 조항보다 우선한다.

## 최종 등록 정책

P0는 미션 필수 전체, P1은 핵심 고유 기능이며 둘 다11/20 구현·검증 목표다. P0와 겹치는 기능은 P0로 둔다. P2는 미션 선택으로 P0/P1 이후, P3는 기타 확장으로 P2 이후다. T38은 게임 기능이 아닌 발표·문서 제출 지원으로11/21~24에 수행한다.

3층 축소안은 폐기하고6층 구성 전체를 채택한다. 기본 공격+추가 공격 타입1종과 버프·전투 연동은 필수 목표다. 같은 인접 효과는 제공원 수와 무관하게 같은 대상에1회만 적용하며 다른 효과는 동시 적용한다. (효과 종류, 대상 인스턴스)로 중복을 제거한다. 가방 수치/확장 칸수·추가 공격의 구체 형태·Meshy 권리/과제 허용만 남은 확인 대상이다.

기존 로드맵·추적표 링크는 과거 조사 참고이며 이번 등록에는 이 문서를 우선한다. 다른 문서는 수정하지 않는다. 필수 기능을 후순위로 넘기거나 축소하지 않는다.

## 공통 완료 기준

구현 하위 Issue는 개별 조건 외에도 개발자가 Unity 컴파일/Console 오류·관련 경고와 제시한 수동 사례를 확인하고 근거를 남겨야 한다. Codex는 Editor·게임 테스트·빌드를 실행하지 않는다. 미검증은 체크하지 않는다. 문서/의사결정 Issue(T38, T39)는 해당 산출물 검토로 검증한다. T36은 개발자 관찰 결과를 기록하는 작업이다.

공통 제외: 점프, 별도 FSM 프레임워크, Repository/DTO/범용 프레임워크, 새 허브·세이브·상점의 임의 도입, 제공 조건을 벗어난 직접 파티클/셰이더 제작. 예상 파일은 개발자가 실제 구조에 맞춰 생성하며 이 문서는 게임 파일을 생성하지 않는다.

### T01 — 이동과 대시의 입력·물리 연결

- 상위: E01

- 목표 일정: 2026/11/10~11
- MVP 필수 여부: 필수

**배경 / 목적**

점프 없이 좌우 이동과 짧은 대시로 전투의 기본 조작을 확보한다.

**구현 범위**

A/D·Space 입력, Rigidbody2D 이동과 정지, 대시 중 재입력 제한을 구현한다. 바닥·충돌체는 기존 구성을 보존해 개발자가 확인한다. 무적 여부·시간·방향 수치는 결정 후 반영한다.

**핵심 설계·알고리즘 고려사항**

**완료 조건**

- [ ] A/D 각각 이동·키 해제 정지·벽 충돌·연속 Space 입력에서 1회 대시만 발생한다. 점프 입력은 없다.
- [ ] 위 공통 검증 기준과 아래 수동 사례의 실제 결과가 기록돼 있다.

**수동 검증 방법**

평지 양방향·벽 앞·정지/이동 중 대시를 확인한다. 무적이 미결정이면 이동만 검수하고 무적 완료로 기록하지 않는다.

**기술 학습 키워드**

Rigidbody2D; Input System; 물리 갱신; 재입력 제한.
