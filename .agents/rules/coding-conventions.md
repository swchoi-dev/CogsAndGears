# Unity C# 분석·구현 가이드 기준

게임 코드 작성 지시가 아니라 개발자 구현을 위한 읽기 전용 검토 기준이다.

- 가독성과 인접 코드 일관성, 작은 책임의 컴포넌트를 우선한다. 불필요한 인터페이스·프레임워크·내부 클래스·`sealed`를 제안하지 않는다.
- 상태는 `enum` + `if-else`/`switch`, 통신은 C# 이벤트로 설명한다. 별도 FSM·State Pattern을 도입하지 않는다.
- 타입·공개 멤버·메서드는 `PascalCase`, 매개변수·지역 변수는 `camelCase`, 비공개 필드는 `_camelCase`. 기존 일관된 규칙과 충돌하면 먼저 확인한다.
- 의미 있는 이름·상수·설정을 사용한다. Unity 직렬화가 필요 없는 로직은 순수 C# 분리를 검토할 수 있다.
- 직렬화 필드명과 공개 API를 보존하고, 잦은 호출의 할당·비용 큰 조회·이벤트 구독 해제를 검토한다.
- 주석은 의도·불변 조건·타이밍에 집중한다. 검증 제안은 null·경계 조건·기존 테스트 구성을 고려한다. 에이전트가 게임 코드·테스트를 생성하지 않는다.
